# 小簿后端编码规范

这份约定用于小簿的 Java 业务模块。以支出录入为第一个可运行示例，不把示例里的预览身份当成正式鉴权方案。

## 分层与命名

| 层 | 职责 | 本项目命名示例 |
| --- | --- | --- |
| `interfaces` | 处理 HTTP、输入校验和身份上下文。只与应用层契约交互，不直接操作实体或数据库 | `ExpenseController`、`recordExpense`、`RecordExpenseRequest`、`ExpenseResponse`、`ExpenseWebMapper` |
| `application` | 编排业务用例、事务与授权。写用例用 Command，读取用例用 Query，结果不泄漏 JPA 实体 | `ExpenseApplicationService`、`RecordExpenseCommand`、`ListExpensesQuery`、`ExpenseResult`、`ExpenseRepository` |
| `domain` | 表达业务概念、值对象与不变量，不依赖 Spring MVC、JPA 或具体数据库 | `Expense`、`ExpenseDetails`；在这里校验金额、分类与业务日期 |
| `infrastructure` | 实现应用层端口、管理持久化与查询，JPA 映射和数据库实现只在这一层 | `JpaExpenseRepository`、`LedgerTransactionEntity`、`LedgerTransactionJpaRepository`、`ExpensePersistenceMapper` |

公开方法用动词并交代意图，查询名能说明实质条件，如 `findByMonthAndCreator`。不为凑层数创建只有透传逻辑的类。跨层 DTO 和持久化映射使用 MapStruct，未映射的目标字段按编译错误处理；业务判断不放进 Mapper。每个业务模块通过用例或明确的端口协作，不绕过应用层直接连对方的 JPA 仓库。

## JPA 与数据库

- Flyway 迁移脚本负责表、索引与约束；Hibernate 只做 `ddl-auto: validate`，不代替迁移。已运行过的迁移不原地改写。
- 单表增改查优先复用 Spring Data JPA 自带的 `save`、`findById` 和派生查询，不另外封装通用 CRUD，也不直接注入 `EntityManager` 做常规操作。账本流水用窄接口，只声明实际需要的方法，不暴露默认物理删除，也不能用裸 `findById` 代替带账本权限和逻辑删除条件的业务查询。
- 应用预先分配 ID 且实体没有版本字段时，用 `Persistable.isNew()` 显式标记新旧状态；加载和插入完成后切换为已存在。这样第一次调用 `save` 走 INSERT，不会因 ID 已有值而当作更新。修改流水时，先按业务范围查到已有实体，再修改；不能用请求数据重新构造一个新实体来更新。
- 简单查询优先派生方法；条件较多时用短命名加参数化 JPQL。过滤、排序和分页交给数据库；只有复杂报表、批处理或 MySQL 特性确有必要时才用原生 SQL，并记录理由、用目标版本验证。
- 业务日期用 `LocalDate` / `DATE`，审计时间按 UTC 写入；复用 Foundation 的时间戳回调，操作者由应用用例提供。流水保留 `created_by`、`updated_by` 和 `deleted`，列表明确过滤逻辑删除。不要把库中已有的 `deleted` 列自行替换为别的软删模型。
- 创建人是审计字段，不是共记权限。正式接口应先校验服务端身份和账本成员权限，再查询该账本；固定身份和按创建人过滤只适用于本地预览。不得为方便联调而开启生产模拟身份。
- 金额以整数分保存；类型和状态按稳定编码落库，不用 Java 枚举序号。统一防重复提交尚未做，不为单一流水表临时加 `submit_key`。

## HTTP 与 XML

- HTTP 映射不重复声明默认请求体格式；只有需要明确区分媒体类型时才设置 `consumes`。
- Maven POM 和后端 XML 每级缩进两个空格，非空容器的开始、结束标签分行，依赖、插件和配置节点逐项展开。简单值和空元素可以独占一行。不要在格式化自身之外把改动扩散到未涉及的 Foundation 模块。

## 提交前验证

1. 项目后端执行 `mvn -f backend/pom.xml verify`，通过格式、静态检查和单元测试。
2. 涉及 JPA、迁移或审计时间的变更，用与目标兼容的隔离 MySQL 重跑。仓库里的 `ExpensePersistenceMySqlTest` 仅在配置 `127.0.0.1` 上的 `xiaobu_expense_test` 时运行，检查金额、UTC 审计字段、账本/创建人隔离、收支方向、逻辑删除、月份起止日和主键冲突时不覆盖已有流水。不要连接线上库。
3. 从真实入口复核受影响流程；支出当前以 H5 交互和接口为准，微信小程序构建通过不能代替真机验收。
