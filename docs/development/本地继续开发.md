# 小生活记账簿 · Vant 4 本地接力

## 本机服务管理

在 Mac 的项目根目录运行 `./scripts/local.sh start`，打开 <http://127.0.0.1:18211/>。脚本使用已有后端 JAR，修改 Java 后先按下节重新构建。需要 Colima、Docker CLI、Node.js 和 JDK 27；自定义 JDK 目录可用 `XIAOBU_JAVA_HOME` 指定。首次启动会补齐缺失的前端依赖，并按需创建独立 MySQL 5.7.44 容器。

- `./scripts/local.sh restart` 重启数据库、后端和 H5。
- `./scripts/local.sh stop` 停止这三个服务，保留 Colima 和数据卷 `xiaobu-local-mysql-data`。
- `./scripts/local.sh status` 查看三个服务的状态。
- `./scripts/local.sh logs` 持续查看前后端日志，按 Ctrl+C 退出查看。


## 正式工程：第一条支出流水

范围及表结构见[支出记账首轮验收](../specs/支出记账首轮验收.md)。后端仅在本地联调 profile 下向回环地址提供支出录入、按月查询接口；目前是独立测试会话，不是微信登录。禁止以当前 profile 部署或连接礼相记数据库。

1. 用 JDK 21 和 Maven 3.10.0，在 foundation 目录运行 mvn -pl foundation-common-data,foundation-common-web -am install，安装本工作区公共制品。
2. 准备隔离的 MySQL 数据库。用当前 shell 的 XIAOBU_DEV_DB_URL、XIAOBU_DEV_DB_USER、XIAOBU_DEV_DB_PASSWORD 注入连接；不把实际值写入版本库。
3. 在 backend 切换到 JDK 27，运行 mvn verify；用 java -jar target/xiaobu-backend-0.1.0-SNAPSHOT.jar --spring.profiles.active=local-expense --server.port=18125 启动。Flyway 只初始化该隔离库。
4. 在仓库根目录运行 npm ci --prefix frontend，再运行 CI=1 npm --prefix frontend run dev:h5；打开开发服务地址，点「记一笔」、选择测试身份，再录入支出。接口可用 python3 scripts/verify-ledger-h5.py 18125 点测，脚本只接受本机联调端口。
5. 2026-11-25 云电脑实测：H5 页面录入 12.30 元，刷新仍只显示一笔同名测试流水；H5 代理到真实隔离 MySQL 5.7.44，Java 服务重启后仍能读回。两位小数、零金额拒绝和审计列均验证。后端通过 `LedgerTransactionPersistenceAdapter` 复用 Spring Data JPA 的 `save` 和 JPQL，Flyway 迁移不变；隔离 MySQL 集成测试补验了跨月起止、方向、删除过滤、账本和创建人隔离及 UTC 审计。Hibernate 对 MySQL 5.7 仍有兼容性警告，只确认本轮场景。小程序只编译，未做真机登录或写入。邀请仍不在该 PR 范围内。


产品简称和助手名均为「小簿」。一期范围与验收规则见[微信小程序一期 PRD](../product/微信小程序一期PRD.md)。

这是当前 Vant 4 H5 试验版的源码、测试和构建产物。不含旧完整原型、礼相记仓库或真实账本，不含任何浏览器本地数据。这版未发布到线上。

## 已定的交互

- 聚焦流水和记一笔；不做人情独立页。礼金往来在同一条流水详情中展示、编辑和删除。
- 记账保留常用横滑；「选分类」面板里直接管理，支出与收入分别新增、排序；支持拖动手柄和上移/下移。调整顺序不改老账目。
- 金额、分类、日期标 *；账户、备注、往来信息选填。同名联系人用不同称呼或关系区分；明确新增后选中，不自动合并也不重复建。
- 往来事由可以选婚礼、生日等，也可以自定义。礼单仍按日常送礼/日常收礼处理，不把事由当独立礼单。
- 底部中央「小簿」进入独立聊天页，长按可直接语音输入，不遮挡流水，不模拟成已接入模型。按当前日期与账本统计本机示例记录，返回保留流水筛选。
- 交互用 390px 浏览器视图点测过分类拖拽/新增/刷新，金额校验，同名去重，自定义事由入账及详情、问账范围与返回。试验版和旧原型共 100 项自动测试通过，未做真实手机/微信验收。

## 移动端字段规范

- 必填项在标签文字后加红色 `*`，间距 3px。以当前操作的保存条件为准。转账两端账户均必填；普通记账的账户可留空；礼单登记必须有人名；新增同名亲友时，称呼或关系才必填。可留空的字段省略「选填」。
- 编辑表单的普通字段一行两列。标签和值均左对齐，标签列宽 84px，列间距 10px。同组输入框、日期、只读值和选择器共用起点；选择器的箭头靠右。金额单位只出现一次。
- 需要空间的主金额、分类网格、事由标签和多行内容采用上下布局。管理入口靠标题行右侧，选项从下一行左侧开始。
- 查询列表的金额靠右，日期和说明放在次行。开关靠右。以上不影响表单的输入值对齐。
- 字段使用可见标签；输入提示仅用于示例或格式。校验失败保留已填值，说明缺少的字段或正确格式。
- 同一字段在新增、编辑和弹层中沿用相同样式。普通文字、金额、日期和下拉值采用无框输入行；卡片可有外边界，行间用细分隔线。输入时保留光标，可用标签颜色提示焦点。用键盘操作按钮时保留可见焦点。
- 同名时展开的称呼、弹层内新增的分类和事由，同样使用 84px 标签列与 10px 间距。行内保存按钮留在输入值右侧。长字段名可以换行。
- 搜索栏、问账消息输入和备份文件选择是独立操作控件，分别保留搜索容器、消息输入区和文件按钮。预填日期等可编辑的必填值仍标星；只读资料仅展示值。
- 录入表单使用 Vant Form 和 Field rules 校验，提交时保留草稿、显示各字段自己的错误，并定位首个错误字段。跨字段错误放在可以修正它的字段下，例如租期倒置提示在到期日下。分类、联系人、转账账户等自定义控件也要注册为 Field；快速记账、连续登记、选择器内新增与编辑均从所属 Form 提交。错误另起一行，标签仍对齐输入值首行。
- 活动礼单的「默认日期」和「默认事由」均可留空，也可在编辑时清除。新登记优先带入礼单默认值；无默认日期时采用当天。已保存的往来保留各自的实际日期和事由。
- 日期使用 Vant Calendar 底部弹层。单日选择用 single，区间查询用 range。跨年合同可切换年、月，确认后回填，取消保留原值。表单内复用 DateField，无框日期行的标签、值和箭头与其他选择行对齐。
- 少量互斥选项使用 Vant ActionSheet，每项独占一行，整行可点；当前项用浅色底和勾标识，禁用项降低对比度。
- 收支类型、收送方向等二选一字段沿用普通标签列和必填星号；值列用等宽分段按钮，浅色底槽、深绿底白字表示当前选项。编辑时方向固定的礼单用只读字段展示。
- 全部 H5 页面禁止原生 select 下拉菜单。短的固定互斥选项使用分段按钮；房屋、账单、权限等单选字段点击后从底部弹出选项，标出当前值。可新增或搜索的长列表使用专用选择页；只读值显示为文字。

### 「记一笔」的业务字段

- 新增、编辑、再记一笔共用相同顺序：收支类型 → 金额 → 分类 → 日期 → 账户 → 备注 → 当前分类的业务字段 → 保存。切换分类只切换末尾的业务区，通用字段保持原顺序。
- 一个业务字段用一张单行卡，字段标签直接说明用途。住房支出在备注后显示「关联租房账单」，点开直接选择账期；普通住房支出可以留空。编辑时保留实付金额，再记一笔时重新选择账期。
- 多个相关字段合为一卡，默认展开。业务卡片统一从第一个字段开始，卡片分组名称供读屏使用。礼金依次放所属礼单、送礼人或随礼对象、事由。后续业务也先放关联记录或对象，再放依赖该选择的补充项。
- 只在当前分类有适用字段时显示业务区。合同条款、亲友档案等长期资料在各自业务页维护。业务字段沿用通用标签列、必填星号和 Vant 字段下方的校验提示。
- 字段标签统一用 14px 常规字重和正文色，主金额只放大数值。选择行空值用「选择账户」「选择账期」这类动作加对象的短语，使用次要文字色；已选值使用正文色。尾部箭头统一为 16px 次要文字色，右缘对齐。
- 可独立维护的账户、礼单支持在选择器内新增。合同派生的房租账期由合同和付款周期生成，选择器只列可关联的账期；尚未设置时提示到「租房 → 合同」设置房租账单。

- 活动礼单的编辑、归档和重新开放集中在礼单摘要右上角的「更多」菜单。可清空的日期选择行沿用 Vant Field 的圆形叉号，点击清空后焦点回到日期字段；必填日期只显示选择入口。
- 可留空的文字、金额、日期和弹层选择字段，有值时在字段内显示圆形清除按钮。按钮独立于行高计算，清空后保持标签、值列和选择箭头的位置；礼单清除后回到对应方向的日常礼单。
- 可留空的事由标签点一次选中，再点同一项取消，点其他项切换。标题行仅保留字段名和事由管理入口。

### 业务提醒接入

在 reminder-sources.mjs 注册业务来源，声明默认提前天数、可选天数及待办生成规则。每条待办提供业务记录编号、发生期标识、到期日、标题、说明、可选展示值，以及目标页面与打开参数。周期业务仅枚举到统一传入的最远提醒日。业务页使用同一来源配置展示提醒设置，按目标参数定位记录并返回提醒列表。

业务决定何时算办完，例如有有效付款流水或已处理该次合同到期。提醒中心统一处理提前天数、关闭、跨日分组、角标和排序。房租付款只由固定账单产生提醒。礼单等业务可在确定触发条件后按同一约定接入。

### 提醒内容规范

- 通用内容包括事项标题、本期日期、办理状态和处理入口。自建提醒另配置提前天数、时刻、重复规则、通知方式及可选的业务关联。列表显示便于辨认的摘要，完整设置放详情。
- 自动付款提醒展示账单名称、所属账期、到期日和应付金额；房租复用该条提醒，可到对应账期付款或关联流水。合同到期提醒展示房屋、到期日及出租方。自建提醒展示用户标题、时刻、周期，详情可打开所关联的账期、合同或礼单。活动礼单须由用户主动关联，礼单默认日期只用于登记。
- 新建提醒默认微信通知，本地只记录偏好。单次预览本次时刻，重复预览接下来三次计划时刻，按提前天数和短月规则计算。

- 自建提醒总是保留在待办列表。微信通知默认开启，可单独关闭。铃铛统一统计已到提醒时间且仍待办理的事项，与置顶「待处理」列表对应。自建事项可在列表标记已办并撤销；付款和合同事项从列表进入对应业务处理。日期支持公历、农历与具名节日；农历与节日支持单次或逐年换算，预览显示实际公历通知时刻。节日指节日本日，放假区间与调休工作日另需年度安排数据。

### 详情页的卡片与列表

- 摘要卡用于需要一起读取的核心信息，例如账户与余额、合同与租期、提醒事项与本期日期。同一对象只用一张主摘要卡；标题已能说清且没有重点数值或状态时，直接从字段列表开始。
- 可逐项查阅的属性用标签和值列表，例如提醒时间、通知方式。有关联记录可打开时显示箭头。多笔流水、账期和押金收退记录用可重复的列表行，便于按日期查找和比较。
- 主要办理按钮放在信息之后。自建提醒默认给创建者本人，表单与详情省略「提醒谁」。

### 记录表单与详情的操作按钮

- 每个操作区只强调一个主动作。新增、编辑使用实心绿色提交按钮，位于字段之后；只有一个操作时占满内容宽度。按钮高至少 44px，圆角沿用全局按钮变量。
- 按当前可执行的辅助操作数决定入口，主操作不参与计数。零项只显示主按钮；一项直接显示动作名称；两项及以上收进「更多操作」。辅助按钮在左、主按钮在右，等宽、间距 10px。菜单用 Vant ActionSheet，保留取消入口。亲友编辑提供合并与删除，退款编辑和转账编辑提供撤销，流水详情提供复记及删除。
- 账目详情的同级属性使用相同的行高、左右内边距与通栏分隔线，只有展开的子项向内缩进。
- 菜单按普通操作、风险操作排列。风险操作标红，沿用原业务确认；合并先选择目标并预览。纯新增页没有维护操作时，只显示提交。只读用户沿用页面权限。
- 两种常用办理方式（如记为已付、关联已有流水）可直接显示，主方式用实心按钮，另一方式用普通按钮。普通操作显式使用 button，只有保存或提交使用 submit。

### 游客与本地演示登录

首次打开显示独立的只读示例账本。点「记一笔」可取消并继续浏览，或点「微信登录」通过本地模拟进入自己的记账表单。示例数据只从内存读取，首次创建的个人账本为空，已有个人账本沿用原数据。登录状态在当前标签页刷新后保留；从左上角的账本菜单退出，回到示例首页。这一流程用于本地验证，后续微信小程序登录需接入服务端。
