# 小生活记账簿 · 微信小程序一期 PRD

版本 0.1 · 产品评审稿 · 2026-11-25

产品简称「小簿」，对话助手也叫「小簿」。本期服务于自己记日常收支，以及两个人或更多成员共用一本账的场景。首个验收目标是两名真实用户各用一台手机，把一笔支出记进同一本账，两端看到相同的金额、日期和记账人。

## 本期交付

| 入口 | 用户能完成什么 |
| --- | --- |
| 首次打开 | 浏览只读示例账本和流水详情。点「记一笔」时出现「微信登录」，也可以取消并继续浏览。登录后回到原先要填的表单。 |
| 流水 | 在当前账本查看和搜索收支，手动新增、编辑、删除和恢复。金额、分类、日期必填，账户和备注可留空。 |
| 账本与成员 | 首次登录拥有一本空白个人账本。可以新建或切换账本，从成员页选好权限并点「邀请微信好友」。受邀人打开分享卡片，确认账本名、邀请人和权限后加入。 |
| 小簿 | 点击进入对话。本期支持文字记一笔日常支出、查询当前账本的收支和分类合计、查看历史或新建对话。 |
| 个人账本资料 | 记账所用账户和分类沿用当前账本的目录。切换账本后，流水、成员、账户及分类随之切换。个人对话历史按用户和账本分别保存。 |

本地 H5 是交互参考。礼金、租房、固定账单、重复提醒及微信通知排在共记流程验收之后。账户管理按已确认原型迁移，普通转账、信用还款和投资买入／赎回均登记为同账本内的双边转账，操作与角色规则见[账本账户验收](../specs/账本账户验收.md#账户管理原型对齐)。

## 一笔账怎样记成

甲在首页选好账本后，点悬浮的「记一笔」，直接填写本账本的流水。保存成功后，列表出现新记录，汇总随之更新。记账人取自当前登录身份；自己看到「我」，其他成员看到可辨认的成员名称。编辑保留原记账人。

乙也可以在「小簿」输入「昨天买菜花了六十八块」。助手显示日期、分类、金额和已识别账户的草稿。只输入「昨天买菜」时追问金额。用户核对后可修改、放弃或确认入账。语音输入暂缓。

小簿支持用自然语言组合查询本人有权查看的业务数据。一期在当前账本内，按日期、分类、账户、记账人等条件查流水、汇总、比较或排行，并可查看账户与分类目录。后续业务按数据源接入同一查询能力；每种问法共用该能力。数据范围、计算口径和验收见[小簿 AI 详细设计](../design/小簿AI功能与技术详细设计.md)。

查询直接回答，并允许打开计算所用的明细。答复显示日期范围，结果按当前账本的可见流水计算。切换账本时，已有草稿始终绑定发起时的账本；需要变更目标账本时重新发起记账。

## 成员权限

一期成员权限已确认，以此表作为小程序实现与验收依据。现有 H5 的可记账成员权限更宽，迁移时需补上按流水创建人校验的规则。

| 操作 | 管理者 | 可记账成员 | 只读成员 |
| --- | --- | --- | --- |
| 查看本账本全部流水、汇总与账户 | 可以 | 可以 | 可以 |
| 新增流水 | 可以 | 可以 | — |
| 编辑、删除、恢复流水 | 本账本全部 | 仅本人创建 | — |
| 邀请、调整权限或移除成员 | 可以 | — | — |

成员退出或被移除后，保留原有流水和署名。打开分享卡片只展示加入所需信息，接受邀请后才可读取账本。邀请过期或被撤销时说明原因；同一成员重复接受有效邀请，直接进入已加入的账本。每次读取和写入均核对当前成员关系，角色变更对已打开的页面也生效。

## 两个人同时操作时

- **连点保存或网络超时。** 提交期间禁用按钮，未确认结果前保留草稿，显示保存状态；重新联网后先核对上次结果，不自动重发。按最新决定不做统一防重组件，不承诺跨网络重放只产生一笔。
- **两人各记一笔。** 两笔都保留，各自署名正确；对方重新打开或刷新账本时能看到最新流水与汇总。
- **同一笔被修改两次。** 如果提交前原单已变化，展示最新记录，保留本次修改供用户核对，再决定是否提交。
- **填到一半被改成只读。** 保存时提示「你的权限已变为只读，这笔账未保存」，账本金额保持原值。若已被移出账本，返回本人可访问的账本。

## 真机验收

使用两个微信账号、两台手机和空白测试账本。每条均以用户能看到的结果验收。

1. **首次使用。** 甲从示例账本进入记账，取消登录仍可浏览；再次点击并登录后直接进入表单。记一笔 32 元午饭，个人账本只有这笔实际支出。
2. **好友加入。** 甲邀请乙为可记账成员。乙能看到甲的 32 元及署名。乙切回自己的个人账本，这笔流水不在其中。
3. **对话共记。** 乙输入「昨天买菜」，被追问后补充「六十八块」。确认前两端仍只有 32 元；确认后，两端查看涵盖这两天的范围，均为两笔、支出 100 元，买菜署名为乙。
4. **异常恢复。** 对在途提交重复点击，界面不重复发送；模拟请求成功但回包丢失，提示先核对且不自动重发。另测两人同时提交不同流水，两笔均出现。
5. **撤权和隔离。** 乙开着编辑页时由甲改为只读，乙保存得到权限提示；甲移除乙后，乙重进和使用旧分享入口都无法读取原账本，甲仍能查到乙先前登记的账。
6. **按创建人维护。** 乙可以查看甲的流水，乙尝试修改、删除或恢复甲的流水时，服务端拒绝操作。乙可以修改、删除和恢复自己创建的流水。分别从页面和接口验证同一规则。
7. **助手查询。** 小簿对指定日期范围给出的总额与流水页一致；点明细可看到参与计算的流水。查看或新建会话后，成员之间的私人对话保持隔离。

## 开发起点

本地原型已验证游客转登录的交互、同一浏览器两种身份接受邀请和改权限、记账与退款、中文金额追问后确认保存。语音用中文音频在桌面浏览器走通过识别和回复。真实微信身份、好友分享、跨设备同步和弱网重试仍需联调。下一步先实现「微信身份 → 账本成员 → 服务端保存流水 → 两台手机读回」，再接小簿的文字对话与确认卡。

自由问账支持在当前账本授权范围内组合查询流水、账户、分类、互转、礼金往来、礼簿及亲友。所有者还可查看有效成员。流水、礼金和互转可按两个期间比较或按指标排行；账户余额及其他目录状态按当前快照回答。
