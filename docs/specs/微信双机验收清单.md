# 微信双机验收清单

状态：代码与本地接口联调。Step 8 的真实微信交换和分享需在获准环境验证；Step 9 的两个真实账号、两台手机结果不得以 H5 浏览器、测试身份或编译替代。本轮不启动文字助手。

## 上机前

- 本机开发者工具联调已确认复用礼相记 AppID，后端只连接小簿独立测试库。双机验收需准备两个有对应开发版或体验版权限的测试微信账号。
- 准备两台手机能访问且已加入小程序请求服务器域名的 HTTPS 测试 API，只连独立测试数据库。发布、代理、域名配置和外部服务变更需另外获准。
- 服务端启用 `wechat-preview`，不能同时启用 H5 的 `local-expense`。沿用 `XIAOBU_DEV_DB_URL`、`XIAOBU_DEV_DB_USER`、`XIAOBU_DEV_DB_PASSWORD`；在服务器密钥环境配置 `XIAOBU_WECHAT_APP_ID` 和 `XIAOBU_WECHAT_APP_SECRET`，不发到聊天、不提交、不打包进前端。应用仍绑定 127.0.0.1，由获准的 HTTPS 反向代理对手机提供服务。
- 在前端环境设 `XIAOBU_WECHAT_APP_ID` 和 `VITE_XIAOBU_WECHAT_API_BASE`，运行 `npm --prefix frontend run build:mp-weixin:preview`。只在构建产物里写入 AppID；本命令不会上传或发布。用有权限的微信开发者工具打开 `frontend/dist/build/mp-weixin` 生成预览，或由已有 CI 生成体验版。
- 客户端使用 [uni.login](https://uniapp.dcloud.io/api/plugins/login.html) 取得一次性登录码，由服务端交换身份并发放自己的会话；不在客户端存储微信密钥或 OpenID。[小程序分享入口](https://uniapp.dcloud.io/api/plugins/share) 用原生分享按钮传入邀请参数，接收人登录后仍需确认加入。

## 两台手机的验收顺序

| 场景 | 甲机 | 乙机 | 需要看到 |
| --- | --- | --- | --- |
| 首次登录 | 点「记一笔」后登录，记测试午饭 32 元 | 用另一账号登录 | 个人账彼此隔离；甲重登仍可读回 |
| 微信邀请 | 生成邀请并用微信分享 | 从好友卡片打开，先看摘要 | 加入前没有甲的流水 |
| 只读加入 | 保持甲账本开放 | 明确接受邀请、查账、切回个人账 | 共享账显示甲的 32 元，乙个人账没有；只读不能新增 |
| 可记账 | 将乙设为可记账 | 再进入共享账，记测试支出 5.40 元 | 两端刷新看到两笔、合计 37.40 元，详情记账人不同 |
| 降权及移除 | 在乙编辑时降权，之后移除乙 | 旧表单保存；重试旧邀请 | 降权拒绝保存，移除后不能读或重加；甲的原流水仍在 |
| 保存状态未明 | 记录在途请求与提示 | 恢复网络后刷新核对 | 不自动重发，不承诺统一防重 |

记录 AppID 所属项目、构建版本、设备型号和每条的通过/阻塞结论，不记录登录码、会话令牌或测试账号隐私。模拟测试单独列，不打真机通过勾。
