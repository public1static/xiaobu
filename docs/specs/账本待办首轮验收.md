# 账本待办：业务聚合

首页铃铛打开当前账本的统一待办。未完成分「待处理」「已计划」，另有「已完成」；铃铛只统计待处理。点击事项回到具体业务记录，不在待办里另存一份合同、账单或流水。首轮接固定账单（包括房租）和合同到期；自建提醒、重复规则与微信通知尚未接入正式工程。

## 来源规则

- 固定账期以账单 ID + 账期月标识。逾期待付保留，每份计划只显示首个尚未支付的未来账期，默认提前 3 天进入待处理；短月按月末，遵守周期、停止月和合同的实到期日。房租仍用同一个固定账期，不重复列成另一个付款任务。V28 仅增加 1900–2100 的月份维表，用于待办展开，匹配小簿常规日期选择范围；完成历史直接读真实付款。
- 待办直接打开对应账期，不需要按月再找一遍。确认付款或关联既有流水后变为已完成，能打开原付款；删除或解除付款关联时，仍有效的该期回到待付。不额外写待办记录或凭据。
- 合同以合同 ID + 到期日标识，沿用已有提前天数和办结规则。办结合同到期不记账、不结清房租，新合同也不继承完成状态。
- 业务日期与提前提醒采用北京时间。有效账本成员可看，写权限仍由具体业务接口校验；非成员不可读。服务端统一排序并按页返回，不由前端拼不同来源的页。

## 接入新业务

每个来源提供稳定的 `source`、`sourceId`、`occurrence` 和日期、展示字段、阶段。SQL 读投影在基础设施层注册，实现 `LedgerTodoSource` 的未完成／已完成查询；使用绑定的 `ledgerId`、`today` 和 `pendingOnly`，保证事项唯一、账本隔离，并让列表与角标复用查询条件。MySQL 5.7 没有递归 CTE，本轮用共享月份维表及受信代码注册的原生 SQL；业务写入继续复用原应用服务。聚合层不按分类编码、名称或来源串写分支，不通过事件把同一状态同步两次。

前端在 `ledger-todo-sources.ts` 注册来源的展示及跳转，通用列表无需修改。增加如礼单活动、保费或工资核对时，先定义发生日和完成事实，再接读投影与原业务入口；不把所有分类自动当作有待办。自建提醒如果接入，可由自己的领域单独存计划和发生记录，再加入同一读接口。

## 验证

- 云端 Chrome 390 px H5 + 真实 Java 接口与独立 MySQL 5.7.44：水电、一期房租和合同到期共同计入角标。付水电新增且只新增一笔，并打开同一付款流水；合同到期办结不动账，未付房租仍留在待办。删除水电付款后该期重新待付。已计划、已完成、只读界面和非成员拒绝均有实测。
- MySQL 集成用例覆盖月末截断、历史欠款、只列下一未来账期、停止边界、跨来源排序与分页。前端格式、自动化测试以及 H5 / 微信构建通过；无微信真机验收。
