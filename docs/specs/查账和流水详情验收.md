# 查账和流水详情验收

范围：TX-02 日期筛选与 TX-03 详情。对照 Vant 原型，将日期入口放在汇总区、备注搜索放在流水上方，点一行从底部打开详情。前端正式工程用 uni-app 日期选择器；不迁入礼金、退款、编辑等未启用入口。

1. 按月浏览不受影响；指定开始和结束日期可跨月，首尾都包含，最多 366 天。不完整或倒序日期会提示。
2. 备注搜索和日期范围可叠加。流水、收入、支出与筛选结余同步更新；清除后恢复所选月份。清空结果时提示没有匹配流水。
3. 点开流水显示分类和金额，其下是记账日期、记账人、账户及已有备注。自己显示「我」，同行有效成员显示其测试名称。
4. 查询始终在当前账本；切换账本不分享数据。非成员不能通过流水 ID 查到详情，已删除流水不会返回。本轮不改数据库结构。

## 服务端分页口径

- `GET /transactions` 支持从 0 开始的 `page`，`pageSize` 默认 20、最大 100；每次返回 `entries`、`totalCount`、期间收支结余和每日总额。月份、自定义日期和备注条件同时用于明细及汇总。
- 数据库按日期、流水种类（当天普通流水在先）、创建时间及 ID 稳定排序后分页，退款按到账日进入列表并冲减当日支出。前端不截完整结果、不拿已加载的明细重新计算全量合计。
- 流水首屏和加载更多使用同一查询。切换账本、月份、筛选或保存后回到第 0 页。用 `scripts/verify-ledger-pagination-h5.py` 在隔离数据库验证跨页、退款、按日汇总、字面备注搜索及无权账本。
- 主流水和退款来自两张表，使用参数化 SQL 做统一分页，是因为 Hibernate 的 HQL 派生 UNION 在隔离 MySQL 5.7 上会生成它不接受的派生列别名。单表写路径不变，继续用 JPA。
