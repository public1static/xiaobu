# 只读邀请加入验收

范围：BOOK-04/05 与 BOOK-08 的只读加入。当前账本所有者明确授权后，受邀人才能读取该账本的历史和新增流水。个人账默认隔离，不接受邀请就没有跨账本权限；不含可记账角色、撤权或微信分享。

1. 测试甲从个人账本生成邀请链接，界面说明对方能读整本账，只读，24 小时内只能有一人使用。
2. 测试乙在独立 H5 会话打开链接。登录前和登录后、确认加入前，都只能看到对方的账本摘要。服务端不允许读取该账本，也不返回流水预览。
3. 乙明确点击「接受邀请」后，能在共享账看到甲所记的支出；不出现记账按钮，服务端也拒绝写入。乙切回个人账仍看不到甲的流水；刷新后可通过账本列表重新进入共享账。
4. 同一成员再次打开已使用邀请会进入原账本，不产生第二条成员关系；其他人不能使用已接受的链接。过期邀请不能加入，所有者不能接受自己的邀请。
5. 浏览器地址用片段携带链接凭证，服务端只存摘要。Flyway V3 只新增邀请和已加入成员关系；唯一约束保障同一个成员只加入一次。当前成员均只读，写路径仍只允许所有者。并发接受使用两条参数化行锁查询：MySQL 5.7 不支持 Hibernate 生成的 `FOR UPDATE OF`，仅此处改用兼容的 `FOR UPDATE`；正常 CRUD 继续用 Spring Data JPA。

只在云电脑的本地 H5、隔离 MySQL 验收。不用于线上，不新增统一防重组件或流水 `submit_key`。
