# 个人账本隔离

本轮覆盖双人共记前置条件 AUTH-02、AUTH-03 和 BOOK-01 的个人账部分。只验证 H5、隔离 MySQL 与独立测试会话；不接微信、不邀请、不提供共享账切换，也不新增流水防重组件。访客只显示登录入口，不读取任何个人流水。

## 怎么验收

1. 在两个独立浏览器会话打开 H5。点「记一笔」可取消登录；再点，分别选择测试甲与测试乙，登录后回到记账表单。两身份的账本 ID 不同；同一身份退出再登录重用原账本。
2. 甲记餐饮 ¥12.30 并刷新。原记录、月份与合计保持；乙刷新，个人账没有甲的记录。重新启动应用后会话需要重登，账本与流水仍可读取。
3. 未登录访问流水接口得到 401；乙以甲的账本 ID 发起读取或写入均得到 403。提交中的记账人字段不参与认定，创建人取服务端会话。退出甲不影响乙会话。
4. 同一身份同时首次登录不会创建两本个人账。账本所有者由数据库唯一约束保证。

## 实现边界

- `local-expense` 是本地专用 profile，拒绝非 127.0.0.1 绑定。测试身份选择入口不验证真实身份，不对公网部署。会话由服务端管理，Cookie 只传会话 ID；禁用 URL 会话标识，API 响应不缓存。
- `POST/GET/DELETE /api/v1/local-session` 分别供测试登录、恢复会话和退出。`GET/POST /api/v1/ledgers/{ledgerId}/expenses` 仅能读取和写入登录人拥有的个人账本。移除前两轮使用的固定预览账本入口。
- Flyway V2 新增 `personal_ledgers` 的所有者唯一约束，不删除或转移 V1 测试数据。前两轮固定身份产生的测试流水不会被自动分配给任一测试账号。
- 联调用 `python3 scripts/verify-expense-h5.py 4173`；从 Vite 同源代理走 API。MySQL 与应用端口均在回环地址，仅用专门的测试数据。
