# 小生活记账簿 · 双人共记一期技术方案与迭代计划

状态：本地设计稿。业务依据为[一期 PRD](../product/微信小程序一期PRD.md)与[双人共记首条流程规格](../specs/双人共记首条流程规格.md)。首条流程先验证记账、分享和双人读回。助手作为第二条接入同一服务。

## 选型及责任边界

| 部分 | 设计决定 | 当前状态 |
| --- | --- | --- |
| 客户端 | uni-app（Vue 3 正式渠道）、TypeScript。H5 与微信端共享流水页、消息和确认卡；登录与分享分别适配。已有 Vant H5 作为交互基线 | 首轮验证记一笔的双端表现 |
| 服务端 | Java、Spring Boot 模块化单体、Maven；按 IAM 基线复用 Foundation、Spring Data JPA 和分层规则 | 独立 Foundation 父 POM 统一管理 Spring Boot 4.2.0 BOM |
| 存储 | MySQL InnoDB；金额以分存为整数，账务日期使用 DATE，版本字段用于并发控制 | 开发、集成测试均覆盖 MySQL 行为 |
| 语音转文字 | 一期暂缓。如重启评估，可参考 DeepSeek 独立 ASR 接口 | 仅保留现有 H5 体验 |
| 文本对话 | DeepSeek 接收文字，理解意图、生成追问或请求调用受限工具。Java 服务负责权限判断、精确计算和入账 | 已选对话供应商，具体模型由服务端配置 |

## 一期文字对话与入账

客户端把用户输入的文字和消息标识交给 Java 服务。服务端按登录身份绑定会话与账本，向 DeepSeek 提供必要上下文及允许调用的工具；工具参数和权限由服务端校验，账本汇总由数据库计算。缺少金额或分类时只追问相应字段。[DeepSeek 工具调用](https://api-docs.deepseek.com/zh-cn/guides/tool_calls/)

例如输入「昨天买菜六十八块」后显示日期、分类和 68.00 元的草稿，用户可修改。确认时复用手动记账用例，重新校验权限；对话失败时保留文字供重试。密钥放在服务端，日志记录请求标识、耗时与错误类型。

DeepSeek 官方将音频转文字作为单独的 ASR 请求，对话使用转写后的文字。按本期范围，微信小程序只交付文字入口，已有 H5 浏览器语音作为原型记录。后续如恢复语音，可评估同一供应商的两步调用。[DeepSeek 语音转文字](https://api-docs.deepseek.com/guides/asr/) · [官方聊天应用指南](https://api-docs.deepseek.com/guides/build_a_chatbot/)

## IAM 后端规范与 Foundation 复用

Foundation 已迁入工作区 [foundation/](../../foundation/README.md)。源自 IAM 修订 72826f9c728e9945d7f5e18da5e3d6293aa754a9，13 个子模块保留已有包名和 artifactId。小簿直接构建独立父 POM 并消费 `com.aegisid:foundation-*:0.1.0-xiaobu.1`，独立版本避免覆盖 IAM 原有 SNAPSHOT。

| 小簿需要的能力 | 归属与使用方式 |
| --- | --- |
| 稳定错误、分页、公共值类型 | foundation-shared-kernel |
| API 信封、全局异常、请求标识、用户提示 | foundation-common-web 的 ApiResponse、ApiErrorResponse、PageResponse 与 GlobalExceptionHandler；消息解析使用 foundation-common-i18n |
| 持久化实体基础、分页适配、实体 ID | foundation-common-data 的 EntityIdGenerator。应用层生成带登记前缀的 UUIDv7，实体 ID、邀请凭证与请求追踪分别建模 |
| 安全、日志、审计与测试 | 按用例装配 foundation-common-security、foundation-common-observability、foundation-common-audit；权限变更等审计由应用明确写入，测试可复用 foundation-test-support |
| 账本成员授权、流水归属、退款及金额规则 | 由小簿业务模块实现；账本 ID 作为业务授权范围，每次操作核对成员关系 |
| 模型调用 | 面向小簿的用例依赖文本对话出站接口。可复用的供应商客户端、超时和错误转换归独立可选 Foundation 模块；记账提示词、工具清单、会话归属和确认规则归小簿。现有 Foundation 模块清单中没有 ASR 或 DeepSeek 客户端 |

**维护方式。** 小簿公共能力在本工程 foundation/ 维护；依赖方向为业务服务 → Foundation。IAM 原仓仍使用其既有版本，若两个系统需要共同升级，由两个消费方分别回归后再切换到同一制品。构建只安装到本机 Maven 仓库。

**服务装配。** 小簿扫描业务根包 com.xiaobu。复用库中声明的 Boot 自动配置；其余 Web 异常处理等组件按需显式导入。在服务集成测试中触发业务异常并核对错误信封，验证装配结果。

**开发约定。** 按业务上下文组织 interfaces、application、domain、infrastructure。Controller 处理输入与认证上下文；WebMapper 转换 Request/Response 与 Command/Query、Result；事务边界在应用用例；领域保持框架独立；PersistenceMapper 转换领域与 JPA 实体。MapStruct 未映射目标字段按错误处理。拒绝访问、并发编辑冲突等由业务错误码驱动，复用 FoundationException、全局映射和中文用户提示。日志用英文并复用 MDC；字段排序分页优先交给数据库。表结构变更使用版本化迁移脚本。沿用 IAM 后端的格式、静态检查、分层测试和集成测试，以及用户的注释与异常消息约定。

当前构建入口：[小簿 Foundation 父 POM](../../foundation/pom.xml)。IAM 规范来源：[原后端父 POM](../../../iam/backend/pom.xml)、[Foundation 父 POM](../../../iam/backend/foundation/pom.xml)、[模块地图](../../../iam/docs/foundation/module-map.md)、[API 契约](../../../iam/docs/foundation/api-contract.md)、[编码规范](../../../iam/docs/development/coding-standards.md)、[分层规则](../../../iam/docs/development/architecture-rules.md)、[对象转换](../../../iam/docs/development/ddd-object-conversion-standard.md)、[异常契约](../../../iam/docs/development/exception-contract.md)、[ID 规范](../../../iam/docs/development/id-generation-standard.md)。

## 首条流程的数据与接口设计

- 用户及身份绑定：内部用户 ID 与外部身份分离，身份来源和外部主体组合唯一。开发环境两个本地身份分别持有独立会话，微信端由后端换取并绑定真实身份。
- 账本与成员：账本记录管理者，成员关系以账本和用户组合唯一，角色区分管理者、可记账和只读。创建首本账和建立管理者关系在同一事务完成。
- 邀请：保存账本、目标角色、凭证摘要、有效期、撤销状态和接受人。预览只返回邀请摘要。事务内检查有效状态并建立成员关系；已接受者重开按当前角色进入，已移除者不能用旧邀请恢复权限。
- 流水：账本、创建人、收支、金额分、业务日期、分类及可选账户和备注，另存版本与删除状态。按账本、日期和 ID 索引分页。不做统一防重，不加提交键；结果未确认时先查账，不自动重发。
- 接口按用例提供登录、当前用户账本列表、创建与预览邀请、接受邀请、查询成员、保存/读取流水及汇总。读取、汇总、修改均以服务端会话与当前成员关系授权。写事务协调成员角色变更与流水写入，编辑按版本检查。对话确认卡与手动录入传入同一保存用例。微信分享卡片传递邀请凭证，登录身份由服务端判定。
